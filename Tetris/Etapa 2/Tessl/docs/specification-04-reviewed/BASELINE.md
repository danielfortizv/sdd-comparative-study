The historical backend command is `pytest -v` from `backend/`; the historical frontend commands are `npm ci`, `npm test`, and `npm run build` from `frontend/`. The development frontend uses `npm run dev`; backend service launch may use the shared pinned Python with `-m uvicorn app.main:app`, working directory `backend/`. Historical Stage 1 evidence reports 9 backend tests passing with one Starlette/httpx deprecation warning and 91% backend coverage; 2 frontend tests passing under Vitest 2.1.9; and a successful Vite 6.4.3 build. Those are historical measurements, not a fresh Stage 2 verification. Historical SonarQube's gate OK had an empty conditions list, so it must not be confused with the enforced Stage 2 gate. Historical reported global coverage was 60.4%, with one vulnerability and 13 code smells; fresh Stage 2 results must use current instrumentation and the controlled gate.

Material risks for implementation/acceptance:

1. This tool's legacy POST `/api/games` returns HTTP 200, and two legacy tests assert 200. The frozen Stage 2 seed asks to keep existing routes compatible without prescribing a new creation status. Shared checker v1.1 and supplemental contract checker v1.0 currently demand 201. Any researcher harness adaptation must explicitly preserve this tool's own baseline and disclose the adaptation, rather than silently changing application behavior to satisfy an ungrounded checker assumption.
2. The legacy active-piece field is `active_piece`, unlike Spec Kit's retained `activePiece`; preserve and normalize only in researcher cross-tool analysis.
3. The legacy explicit row-zero locking game-over rule (Req-26) and its test must be considered when specifying queue draws and terminal behavior. The existing domain path can terminate before attempting a normal new spawn.
4. The current frontend has a single global in-flight Boolean and effect dependencies on complete game state. Stage 2 needs deterministic generation ownership, delayed response-body checks, exact adaptive timer boundaries, and tests that genuinely force stale A/B requests and unmount behavior.
5. Historical Tessl skill activation stalled. Status/context calls must be observed and logged; a fallback reading already-vendored context is a disclosed integration limitation, not proof that a stalled call succeeded. Brownfield work does not require rerunning a greenfield scaffold or plugin installation.
6. Three- and four-row scoring are isolated domain rules: canonical unrotated pieces have height at most two. Their fixtures must be labeled as such and must not be presented as ordinary reachable UI clears.
7. The common frozen Stage 2 seed remains at `../shared/seed.md`; use the exact same extracted English block and log effective submitted input separately from launcher intent.
