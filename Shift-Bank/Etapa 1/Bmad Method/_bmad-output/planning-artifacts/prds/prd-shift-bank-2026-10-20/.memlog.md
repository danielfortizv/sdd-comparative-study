- (decision) Authenticated mock user is single fixed persona 'Alex Morgan' (ID: cust_mock_001) pre-seeded without login/auth overhead
- (decision) Account portfolio pre-seeded with 3 accounts: Checking, High-Yield Savings, Emergency Reserve
- (decision) Single currency strictly enforced: USD ($), avoiding multi-currency conversion complexity in Stage 1
- (decision) Sensitive transfer threshold established at strictly greater than ,000.00; <= ,000 executes immediately
- (decision) MFA mechanism is a mock 6-digit OTP challenge (universal code 123456 or dynamically hinted in dev)
- (decision) MFA security parameters: 5-minute expiry (300 seconds) and maximum 3 failed verification attempts
- (decision) Monetary precision policy: integer minor units (cents) internally and fixed 2-decimal string API serialization to prevent floating-point inaccuracies
- (decision) Transfer atomicity enforced via atomic transaction; conservation of money invariant guaranteed across user accounts
- (decision) Movement ledger is dual-entry and immutable: debit record on source, credit record on destination referencing same transfer ID
- (decision) Self-to-self transfers prohibited at both UI level and backend validation (SAME_ACCOUNT_TRANSFER_NOT_ALLOWED)
- (decision) Zero and negative transfers prohibited; minimum transfer amount is .01
- (decision) Strict overdraft prohibition: balance checked before any transfer initiation or MFA challenge issuance
- (decision) Concurrent submission protection: client-side submit lock plus server-side idempotency key
- (decision) MFA cancellation/abandonment leaves balances untouched and marks challenge CANCELLED
- (decision) Movements ordered chronologically descending (newest first) with empty-state handling for accounts without movements
