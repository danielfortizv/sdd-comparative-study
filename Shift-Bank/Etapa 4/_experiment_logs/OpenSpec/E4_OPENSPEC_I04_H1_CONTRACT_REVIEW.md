### Preferred option for researcher review — D (gated), with immutable legacy provenance

Recommend Option D for review because the guide defines Stage 4 as a disruptive evolution of each tool's own Stage 3 application, not a new bank. D is the only option that can preserve an explicit migration lineage into the D-02 accounts while retaining original IDs/history as provenance. This is **not approval to migrate** and not a claim that value preservation and fixed D-02 balances are already reconciled.

Hard caveat: inherited COP-labelled seed values do not map to the fixed D-02 USD opening amounts under any rate supplied in the contracts; no COP rate is provided. Therefore a policy must specify whether the active ledger preserves converted legacy value (which may not equal the fixed D-02 values) or reaches exact D-02 balances through an explicitly recorded reconciliation/adjustment (which is not pure value conservation). If the researcher requires both economic value conservation and exact D-02 balances, the available evidence/contracts do not establish a valid solution; the researcher must resolve that conflict before migration specification. No rate, adjustment, mapping, or production balance has been chosen.

A safe D design should treat source balances as a cutover snapshot unless a verified chronological event history proves another bootstrap. Imported historical transfers must be preserved for inquiry but must not also affect opening projections if their effects are already reflected in the snapshot. Use an idempotent migration marker/batch, one migration event sequence, replay-from-source tests, and source-vs-target reconciliation assertions. Preserve the old audit chain and never recast its entries as domain events. These are design/test requirements, not implementation instructions.
